# Roadmap

## v0.9.0

The distribution milestone: the first version anyone can install without Xcode and reach a working dictation on, without being told how. Nothing else belongs here.

- [ ] **Notarize and publish a downloadable DMG.** Two-pass — staple the app, build the disk image from the stapled app, then notarize and staple the image — so a copy dragged out of the DMG still validates offline. Verify from a real download rather than a local file: only a file macOS has flagged as quarantined exercises Gatekeeper at all.
- [ ] **Publish the Homebrew cask.** `Casks/scriber.rb` lives in the separate `homebrew-tap` repository, so `brew install --cask gafiegarcia/tap/scriber` needs no tap step first. Bump it in the same release that produces the DMG it points at.
- [ ] **Verify the first release on hardware that never had Xcode on it.** A second macOS user account covers the clean permission and Keychain state; a machine on the oldest supported macOS covers the deployment floor. Neither is optional for the first one.
- [ ] **Let setup choose a shortcut and prove it works.** `defaultHold` is `fn` alone (`ScriberCore/CoreModels.swift:38`), which does not exist on most non-Apple keyboards — their Fn is handled inside the keyboard's firmware and never reaches macOS — so the default is silently dead and setup only prints it as a fact. Offer `fn` preselected, three or four named alternates carrying the reason someone would pick each, and the existing `ShortcutRecorderView` as **Record your own…**, then hold Finish Setup disabled until one press registers. Requiring the press is what removes any need to know what keyboard is attached: do not add Fn detection instead, because macOS sets the same function flag on the arrow, function, and navigation keys of every keyboard (`ScriberCore/CoreModels.swift:1069`), so a press that looks like `fn` proves nothing. Gaf's own alternate is `fn+^+⌥`, worth offering as a named entry. This replaces the sentence at `Views.swift:1348`, which is labelled `Defaults:` but interpolates the current bindings — true on a fresh Mac and wrong for anyone who changed a shortcut and then redid setup. Keep this to one step; the overhaul it was pulled out of is still unscheduled.

## v0.10.0

- [ ] **Walk every window with VoiceOver.** Nobody has, so what an assistive user gets is unknown rather than known-good — which is fine for one user and not for a distributed app. Labels exist where someone thought to add them and are absent where nobody did, and the two states are indistinguishable from reading the source: `accessibilityIdentifier` outnumbers `accessibilityLabel` roughly three to one and does nothing for VoiceOver, so a file can grep as full of "accessibility" while announcing badly. Turn VoiceOver on and tab through the main window, Settings' five tabs, onboarding, and every pill phase. Two known shapes to look for: a control whose only content is an SF Symbol announces as its symbol name, and repeated controls in a list announce identically unless each is named for its own row. A code audit cannot replace this — SwiftUI builds no accessibility tree until an assistive client attaches, so neither reading the source nor querying the app from outside without Accessibility permission shows what is actually published.
- [ ] **Redesign the menu bar menu.** Follow the Claude menu reference: lead with Scriber, show the marketing version and build beneath it, and place an Open control on the trailing edge. ([Notion task](https://app.notion.com/p/3ab71937040280298fa7eb2c10a3ff43))
    - Show ElevenLabs credit usage in the menu bar menu. Reuse the existing Usage display in Settings, "cloning" it into the menu bar if possible
    - "Paste/copy last transcription" or "Recent dictation", showing submenu on hover that shows last 3-5 successful transcripts which when clicked will be either copied to clipboard or pasted to the cursor
- [ ] **Overhaul Settings layout.**
    - Change "Transcription" section name in setting to avoid confusion: under Dictation tab, the “Transcription” section naming doesn’t make sense, as it may conflict with a future long-form Transcription feature I may introduce to Scriber. It should be changed. My draft: Dictation settings, Dictation options, Options, Configuration. I’m not sure what to pick, I need a section name with a meaning that a normie user can immediately understand/infer.
    - Search Settings: Type "mic" in the Settings window and land on the setting, whichever of the five tabs holds it. Tabs made Settings scannable; this is for the case where the user knows the setting's name but not which tab owns it. SwiftUI supplies nothing here — it needs an index of every setting with its keywords, a field, results, and a jump that shows which control it landed on. (Update) also consider implementation difficulty now that Settings window is a tabbed interface.
    - Tell the user where the missing permission lives when account access is denied. A key can verify for Speech-to-Text and still be refused account usage, and the tip that covers it (`AppCoordinator.swift:727`) says "Enable User → Read in ElevenLabs to show credits" — it names the permission but not where to set it. Replace that sentence with the path that reaches it: find the key at <https://elevenlabs.io/app/developers/api-keys>, open its three-dot menu, choose Edit, and enable User access under Administration. **Ask Gaf before changing the first sentence** ("This key is scoped for Speech-to-Text but not account usage"), which may stay as it is.
- [ ] **Offer a top pill position** beneath the notch, alongside the current bottom placement. ([Notion task](https://app.notion.com/p/3a671937040280e9869df52acd0c13a7))
- [ ] **Integrate the pill into the MacBook notch.** Treat this as a separate capability from placing the existing pill beneath it.
- [ ] **Make a card's date readable without scrolling it to the top.** The titlebar's day strip only names the day at the very top of the list, so a card lower down — especially on a light day with only a few entries — has no visible date at all until it is scrolled there. The cheap fix: show the card's full date, greyed out, in its three-dot menu, above **Delete…**, so the date is at least reachable per-entry without scrolling. The fuller fix: put the date directly on each card and have it hand off to the titlebar label exactly when the card reaches the top — the same crossing point `DictationHistoryView.currentTitle` already computes — so the label never exists in both places at once. Try the cheap fix first; the transition in the fuller one is the hard part and may not be worth it.
    - Preferred shape for the fuller fix: a persistent date label above every card *except the first*, since the titlebar already names that one. It sidesteps the hand-off entirely — nothing has to animate at the crossing point, because no card ever needs a label at the moment the titlebar is showing its date.
- [ ] **Pivot to a single dictation shortcut.** One shortcut covers both modes: released before a threshold starts hands-free, which the same shortcut or the pill's ✓ stops; held past it records for as long as it is down. Replaces the separate `holdShortcut` and `toggleShortcut` (`Preferences.swift:39`) and their independent enable flags. Pick the threshold while building — Cloudless Voice and Spokenly both work this way, so compare against them rather than guessing. Offer ready-made combinations in the picker, not only record-your-own. This settles the double-tap-a-modifier idea against it: a double tap and a quick tap are competing readings of the same key. ([Notion task](https://app.notion.com/p/3b771937040280d08b54de821025b0f9))
- [ ] **Tell the left modifier keys from the right ones.** `Right ⌘` and `Right ⌥` held alone are the best free triggers on any keyboard — nobody starts a shortcut with them — and Spokenly offers exactly those. Scriber cannot: `KeyModifiers` (`ScriberCore/CoreModels.swift:5`) carries one `.option` and one `.command` with no side, which is why `ReservedShortcuts` refuses a lone modifier for everything but `fn`. The side is readable from the physical key code on a `flagsChanged` event — 55 and 54 for ⌘, 58 and 61 for ⌥, 59 and 62 for ⌃, 56 and 60 for ⇧ — so the work is carrying it through the chord type, the recorder, the global tap, and the stored preferences, and making a bound right key refuse its left twin. Build it with the single-shortcut pivot: both rewrite chord matching, and doing them separately means writing that stateful matching twice. Add the winners to `ShortcutPreset.all` when it lands.
- [ ] **Accept non-key dictation triggers.** A four- or five-finger trackpad touch and the extra mouse buttons (4, 5, 6) can each start a dictation, alongside key chords. Spokenly does the trackpad one, so treat it as proven rather than exploratory. Build after the single-shortcut pivot lands — every trigger has to report press and release timing, and that contract is what the pivot defines. The task page also proposes double-tapping a modifier, which the pivot rules out for the reason recorded above; whichever ships first decides the other, so do not treat the two pages as one piece of work. ([Notion task](https://app.notion.com/p/3b3719370402804d88cfe80d730c6943))
- [ ] **Add the missing space when pasting after a sentence.** When the character before the cursor ends a sentence (`.`, `?`, `!`, and the same followed by a closing quote) with no space after it, insert one before the transcript. Regex detection is enough. `PasteService.textState(of:)` (`PasteService.swift:455`) already reads the focused field's value and selected range for paste-fail detection, so the preceding character is reachable there; fall back to pasting unchanged when the element exposes neither. ([Notion task](https://app.notion.com/p/3b771937040280e69390c2ba149af794))
- [ ] **Let a truncated dictation entry expand in place.** A card's transcript stops at four lines (`DictationHistory.swift:307`) and ends in an ellipsis, so the only way to read the rest is to copy it out — and the cutoff moves with the window, taking more of the transcript as the window narrows. Offer a **See more** control on entries that are actually truncated, lifting the line limit in place when it is clicked. **Ask Gaf if truncation turns out not to be detectable**; the shape above assumes it is. ([Notion task](https://app.notion.com/p/3ba719370402803a8978eb4d1c39da5c))
- [ ] **Make paste-fail detection a toggle-able setting.** Some users may not like the interruption of the feature, and just like the dictation get auto-pasted as quickly as possible and optionally copied. **The task page carries a full design Gaf considers fragile and wants refined before anything is built — read it and talk it through first.** ([Notion task](https://app.notion.com/p/3b871937040280a89e80ea4c7222d2b4))

- [ ] **Install updates rather than only announcing them.** Scriber checks GitHub daily and points at the release page; Sparkle would download and apply the update itself. Deferred until the release pipeline has shipped twice, because Sparkle brings the project's first third-party dependency, an EdDSA key whose loss cannot be recovered from, a hosted appcast, and nested code signing that has to survive notarization — none of which should be debugged alongside a release process that has never run. Generate third-party notices when it lands; the app declares no such dependency today.

## Long-term

- [ ] **Support other providers like Groq** (which also has a generous free tier just like ElevenLabs).
    - Changing the Settings tab name from ElevenLabs to something else. Could be "Providers", "API keys", or something else.
    - Reorganize that tab, now that each provider owns its own API Key and (possibly) Usage section. May need to redesign to ensure good UX and proper visual hierarchy.
    - Explore Groq Whisper API and incorporate it into Scriber engine.
    - In anticipation of the upcoming long-form Transcription feature (which may own its own tab in Settings when it arrives), Dictation tab should include an option to select the provider for Dictation—when Transcription lands, it can be configured to use a different provider (yeah I think that's cool). The setting/option row should have a "configure providers..." (copy wording may change) button to jump to the providers settings tab and a picker that lists configured providers. I currently imagine the best UX for this is to only list *configured* providers indicated by a successful verification (reference: ElevenLabs current "Verified" badge check); so the Picker would show cleaner lists, excluding unconfigured providers and providers with unverified API keys.
    - Just below that setting (or in the same group), also add a model picker, as Groq provides two Whisper v3 variants (large and Turbo if I'm not mistaken). Users have the freedom to choose, but Scriber always recommend the better models based on interal testing by adding "(Recommended)" tag on the picker option or an icon that indicates similar intent/info (⭐ for example).
    - Tag ElevenLabs (only list Scribe v2 for now, model picker greyed out) as "(Recommended)" because it's the one I use, tested, and doesn't need post-processing layer to produce filler-free, accurate transcripts with auto-punctuations. Whisper v3 (and the Turbo variant) is also good in this regard, but falls behind in WER benchmark by considerable points compared to ElevenLabs Scribe v2. To summarize:
        - Recommended Provider: ElevenLabs (Scribe v2 as the only model option, for now)
        - Recommended Model from Groq: to be determined
- [ ] **Build the long-form Transcription workspace.** Settings has a Dictation tab, and Transcription options get their own tab beside it. The main window's workspace control becomes a picker when this lands.
- [ ] **Order the toolbar for two workspaces.** When the workspace control stops being a plain name, lay the toolbar out like this:

      ```
      [ Dictation | Transcription ]  353 dictations   ·gap·   ⚙  ⚠        ·······  [ Search ]
      └──────── what you're looking at ────────┘        └── app-level ──┘
      ```

      The switcher leads because it is the subject every other item describes and the one control aimed at by muscle memory; the count follows it as its subtitle, and being adjacent is what keeps it reading as one rather than as a clickable fact of its own. The fixed gap stands in for the trailing cluster this toolbar cannot have, marking Settings as app-level rather than part of the workspace, and it survives the switcher being wider than a word of text. Settings before the warning, so the permanent control holds the fixed position and the transient one grows into the gap.
- [ ] **Decide the workspace switcher's control.** Apple's guidance is a tab view for view switching and a segmented control only in a toolbar or inspector, and this switcher is in a toolbar — so both readings are defensible. Evaluate `TabView` first, because Dictation and Transcription are two top-level destinations with their own list, query, and scroll position, which is what a tab view models and a picker only imitates. Reject it if it cannot mount its bar in the existing toolbar beside the count, Settings, and search, or if it wants per-tab toolbar items: a toolbar whose items vary by destination is what this window crashed on.
- [ ] **Overhaul onboarding.** Current onboarding is one-paged, boring first-time setup with incomplete "get started" information. Watch someone unfamiliar run the current one on a Mac that has never had Scriber before scoping this: the shortcut step is already pulled out into v0.9.0, and what is left may be smaller than it looks from here.
    - Refer to Wispr Flow onboarding: one-page per step, carefully crafted design.
    - Give **Mute other audio while recording** a step of its own. It is off by default and its consent dialog already explains the grant, but the toggle sits among the trailing options where a first-time user meets it as an afterthought rather than a decision. Ask it as a step, in the same shape as the permissions above it.
    - Give System Audio Recording a row on the Permissions tab. It cannot report status the way the others do: `AVCaptureDevice.authorizationStatus` covers the microphone, `AXIsProcessTrusted` covers Accessibility, and `CGPreflightScreenCaptureAccess` covers screen capture, but Core Audio ships no preflight for process taps — the only way to read the state is to attempt a tap, which is what raises the prompt. So decide what a row with no readable status says: a signpost with an **Open Privacy & Security** button, or a lagging report derived from whether the last mute attempt failed. `Views.swift:850` already renders that failure with a working button, so the row must not duplicate it.
    - Follow macOS on what the Accessibility permission is called. In macOS 27 beta 5 the System Settings pane Scriber sends people to is **Device Control and Data Access**, not **Accessibility**, so every place Scriber says "Accessibility" names something the user cannot find — the recovery pill, onboarding, the Permissions tab, and the README. Wait for the stable release before changing any of it; a beta name can still move. Pick copy that serves macOS 26 and 27 alike rather than naming one, since Scriber supports both and the permission is the same grant either way. `AXIsProcessTrusted` and the trust-change notification are unaffected: the toggle is picked up within a second in beta 5, most often through the notification rather than the poll.
    - Make onboarding's meter read like the pill's. Both already draw the same `AudioLevelWaveform` at the same cadence, so what separates them is presentation: the pill gives it 58×24 pt in red over its own material, onboarding stretches it to 42 pt tall and full width in the accent colour over a `.quaternary` panel. A bar never falls below 2 pt, so the taller the frame the more a real but quiet signal collapses into the same flat line as no signal at all — the distinction the step exists to show. Match the pill's proportions and contrast rather than inventing a second meter; that rendering is the one legible enough to catch a stream going silent mid-recording.
    - Leave one meter behind, not two. Sharing the view was not enough to stop the divergence above, because each call site still chose its own frame, colour and backing. Give `AudioLevelWaveform` named presentations to pick from rather than raw numbers, and make its 2 pt bar floor proportional to the frame instead of fixed, so a quiet signal reads as quiet at any size and a third call site cannot reintroduce this by choosing a taller box. It also lives inside `PillController.swift`, which is what makes every other use look like a borrowing; a view two features depend on belongs in its own file.
    - Make the microphone step prove itself rather than offer itself. `OnboardingView` already runs a live meter and flips a label to “Audio signal detected” (`Views.swift:1174`), but nothing requires the user to speak into it, so setup completes with the microphone never once tested. Gate the step on signal actually observed. Watching a moment is not enough to trust: macOS can mute a capture stream seconds after it starts — input volume at its minimum does exactly this — so the meter reads healthy at first and drops to digital silence afterwards, and a user who speaks immediately sees a passing test either way. Watch long enough for that to surface, and treat the drop as a failed test rather than a completed one. `MicrophoneDropoutPolicy` already names the floor that separates a muted stream from a quiet room.
- [ ] **Offer a theme override.** Add an Appearance section to Settings' General tab with a picker for System (default), Light, and Dark, applied through `NSApp.appearance`. Decide what the override does to the pill before building it: the pill is an `NSPanel` floating over other apps' windows and today follows the system setting, so a forced Light pill can sit over a dark app — consistent with the rest of Scriber, inconsistent with whatever is behind it.
- [ ] **Extend window-owned search to Transcription.** After the long-form Transcription workspace exists, reuse the persistent native search item with a contextual `Search Transcriptions` placeholder, retain a separate query for each workspace, and make Command-F focus the active searchable workspace.
- [ ] **Add an all-content search scope.** After Dictation and Transcription search both exist, let users broaden the current query without replacing it, keep the selected scope visible while text is present, and present mixed results grouped by workspace.
- [ ] **Explore Apple Foundation Models for post-processing.** Blocked on Scriber reading the text around the cursor, which it does not do today. Size each request against the model's context window — half of the smaller of its input and output limits, converted to words, taking the low end of that estimate — and refuse anything longer rather than sending a truncated request. ([Notion task](https://app.notion.com/p/3a67193704028005b4edff99d44ab13b))
- [ ] **Sweep Scriber against Mac App Store acceptance requirements.** Submission is ruled out — the store requires the App Sandbox, and global shortcuts and cross-app insertion cannot work under it — so run this for the quality bar rather than for a listing. The target is an app that adheres to the store's requirements and best practices on its own merits and would be eligible but for the permission it needs. ([Notion task](https://app.notion.com/p/3ba7193704028014a39ee8466c3b3be2))
- [ ] **Keep the keyterms list usable when it is long.** Scriber accepts 1,000 keyterms (`ScribeClient.swift:169`) and Settings draws every one as a row inside a single Form row, so a few dozen push the History section off the Dictation tab with no scroll of its own. **Ask Gaf to settle the shape first** — scroll inside a fixed-height card, collapse to a count, move the list into a sheet, or a wrapping token field. ([Notion task](https://app.notion.com/p/3ba7193704028188a25dd2d11d69fe44))
